# Paseo App 端三项改动 · 实施计划

> 范围：仅 `packages/app`。不动 daemon、不动 server、不动协议层。
> Android 真后台保活只针对 Android；iOS 在真后台被 OS 暂停 JS WebSocket，不在本次范围。

---

## 0. 现状校准（很重要，不要被直觉误导）

读完代码确认以下事实：

1. **WebSocket 不是按 panel 起停的**
   - `HostRuntimeController` 是全局单例，`DaemonClient` 一份。
   - `SessionContext` 全局订阅 `agent_stream`，把所有 agent 的事件写进 `session-store.agentStreamHead/Tail`。
   - **结论**：app 进程活着 → WS 活着 → 所有 agent 的流一直在累积，跟当前看哪个 panel 无关。

2. **app 内切 panel "看起来在加载"的真因**
   - `workspace-screen.tsx:2813-2817` 用 `useMountedTabSet({ cap: 3 })` LRU 卸载多余 panel。
   - `agent-panel.tsx:728-733` panel 重新 focus 时无条件调 `ensureAgentIsInitialized` → `setInitializing(true)` → 闪 spinner。
   - **结论**：本次不动这块（你确认改动 3、4 不做）。

3. **队列功能底层已就位**
   - `composer-actions.ts:queueComposerMessage` 写入。
   - `session-context.tsx:651-671` 在 agent `running → 非 running` 时自动出队。
   - **结论**：本次只做默认行为切换 + UI 视觉。

4. **Preferences 已按 provider 分桶存**
   - `use-form-preferences.ts:providerPreferences[provider] = { model, mode, thinkingByModel, featureValues }`。
   - composer 改 model 走的就是这份存储，settings 段直接复用即可。

5. **Android 真后台保活的本质**
   - 现有的 WS 单例已经在跑，**不需要在 service 里另起一条 WS**。
   - notifee foreground service 的作用是"让 OS 不杀 JS thread"，已有 WS 自然保活。

### `agent-section.tsx` 骨架

```tsx
import { useMemo } from "react";
import { View, Text, Pressable } from "react-native";
import { useFormPreferences, mergeProviderPreferences } from "@/hooks/use-form-preferences";
import { useProvidersSnapshot } from "@/hooks/use-providers-snapshot";
import { buildProviderDefinitions } from "@/utils/provider-definitions";
import { CombinedModelSelector } from "@/components/combined-model-selector";
import { SegmentedControl } from "@/components/ui/segmented-control";
import { Switch } from "@/components/ui/switch";
import { SettingsSection } from "@/screens/settings/settings-section";

export function AgentSection() {
  const { preferences, updatePreferences } = useFormPreferences();
  const providersSnapshot = useProvidersSnapshot();

  const availableProviders = useMemo(() => {
    const defs = buildProviderDefinitions();
    return defs.filter((def) => {
      const entry = providersSnapshot.entries?.find((e) => e.id === def.id);
      return entry?.enabled && entry.status === "ready";
    });
  }, [providersSnapshot]);

  const selectedProvider =
    preferences.provider && availableProviders.some((d) => d.id === preferences.provider)
      ? preferences.provider
      : (availableProviders[0]?.id ?? null);

  if (!selectedProvider) return null;

  const providerDef = availableProviders.find((d) => d.id === selectedProvider)!;
  const providerPrefs = preferences.providerPreferences?.[selectedProvider] ?? {};

  return (
    <SettingsSection title="Agent">
      {/* chip row */}
      <View style={chipRow}>
        {availableProviders.map((def) => (
          <Pressable
            key={def.id}
            onPress={() => updatePreferences({ provider: def.id })}
            style={[chip, selectedProvider === def.id && chipActive]}
          >
            <Text>{def.label}</Text>
          </Pressable>
        ))}
      </View>

      {/* key=selectedProvider 强制重渲，自动回显该 provider 全部配置 */}
      <View key={selectedProvider}>
        <ModelRow
          provider={selectedProvider}
          modelId={providerPrefs.model}
          onChange={(modelId) =>
            updatePreferences((p) =>
              mergeProviderPreferences({
                preferences: p,
                provider: selectedProvider,
                updates: { model: modelId },
              }),
            )
          }
        />
        <ModeRow
          modes={providerDef.modes}
          value={providerPrefs.mode}
          onChange={(mode) =>
            updatePreferences((p) =>
              mergeProviderPreferences({
                preferences: p,
                provider: selectedProvider,
                updates: { mode },
              }),
            )
          }
        />
        <ThinkingRow
          modelId={providerPrefs.model}
          value={providerPrefs.thinkingByModel?.[providerPrefs.model ?? ""]}
          onChange={(level) =>
            updatePreferences((p) =>
              mergeProviderPreferences({
                preferences: p,
                provider: selectedProvider,
                updates: {
                  thinkingByModel: { [providerPrefs.model ?? ""]: level },
                },
              }),
            )
          }
        />
        <FeaturesRow
          provider={selectedProvider}
          values={providerPrefs.featureValues}
          onChange={(featureValues) =>
            updatePreferences((p) =>
              mergeProviderPreferences({
                preferences: p,
                provider: selectedProvider,
                updates: { featureValues },
              }),
            )
          }
        />
      </View>
    </SettingsSection>
  );
}
```

## 4. 改动一 · Android 真后台保活

### 目标

切到其他 app / 锁屏 / 长按 home 后，只要 paseo 进程还活着，就持续接收 daemon 推来的 token，不是回到 app 才开始加载。靠 Android foreground service + 常驻通知来防止 OS 杀 JS thread。

### 选型

- **`@notifee/react-native`** — 直接做 foreground service，notification 控制丰富。
- 不用 `react-native-background-actions` —— 它要 HeadlessJS、和现有 RN 单例 store 不太兼容。
- 不用 `expo-background-task` —— 它是 deferrable（最少 15 分钟），不是常驻。

### 依赖

```bash
npx expo install @notifee/react-native
```

### `background-keepalive.android.ts`

```ts
import notifee, { AndroidImportance } from "@notifee/react-native";

const NOTIFICATION_ID = "paseo-bg-keepalive";
const CHANNEL_ID = "paseo-keepalive";

let started = false;
let channelEnsured = false;

async function ensureChannel() {
  if (channelEnsured) return;
  await notifee.createChannel({
    id: CHANNEL_ID,
    name: "Paseo background connection",
    importance: AndroidImportance.LOW,
  });
  channelEnsured = true;
}

export async function startKeepalive(): Promise<void> {
  if (started) return;
  await notifee.requestPermission();
  await ensureChannel();
  await notifee.displayNotification({
    id: NOTIFICATION_ID,
    title: "Paseo",
    body: "Streaming agents in background",
    android: {
      channelId: CHANNEL_ID,
      asForegroundService: true,
      ongoing: true,
      importance: AndroidImportance.LOW,
      smallIcon: "ic_notification",
      pressAction: { id: "default", launchActivity: "default" },
    },
  });
  started = true;
}

export async function stopKeepalive(): Promise<void> {
  if (!started) return;
  started = false;
  try {
    await notifee.stopForegroundService();
  } finally {
    await notifee.cancelNotification(NOTIFICATION_ID).catch(() => {});
  }
}

export async function updateKeepalive(body: string): Promise<void> {
  if (!started) return;
  await notifee.displayNotification({
    id: NOTIFICATION_ID,
    title: "Paseo",
    body,
    android: {
      channelId: CHANNEL_ID,
      asForegroundService: true,
      ongoing: true,
      importance: AndroidImportance.LOW,
      smallIcon: "ic_notification",
    },
  });
}
```

### `use-android-keepalive.ts`

```ts
import { useEffect } from "react";
import { AppState, Platform } from "react-native";
import { useAppSettings } from "@/hooks/use-settings";
import { startKeepalive, stopKeepalive } from "@/native/background-keepalive";

export function useAndroidKeepalive(): void {
  const { androidBackgroundKeepalive } = useAppSettings();

  useEffect(() => {
    if (Platform.OS !== "android") return;
    if (!androidBackgroundKeepalive) {
      void stopKeepalive();
      return;
    }

    const sub = AppState.addEventListener("change", (next) => {
      if (next === "background" || next === "inactive") {
        void startKeepalive();
      } else if (next === "active") {
        void stopKeepalive();
      }
    });

    return () => {
      sub.remove();
      void stopKeepalive();
    };
  }, [androidBackgroundKeepalive]);
}
```

### 风险与注意

- **国产 ROM 激进杀进程**：foreground service 也未必能完全防小米/华为/OPPO/vivo 的强制清理。无法在代码层完全解决，需要在 docs/android.md 里告知用户加白名单。
- **Google Play 审核**：`foregroundServiceType="dataSync"` 通常能过，提交时审核备注写"持续接收用户自有 dev daemon 的实时输出"。
- **耗电**：用户已确认不要管省电问题。
- **协议兼容性**：本次改动不碰 WS 协议，符合 CLAUDE.md 协议向后兼容约束。
